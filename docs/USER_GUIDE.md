# User Guide — Interactive Simulation Console

## Coordinate model

The backend uses `LOCAL_NED`:

- X = North
- Y = East
- Z = Down, so altitude above the local origin has a negative Z

The normal web UI hides the confusing negative Down convention and asks for:

- **North (m)**
- **East (m)**
- **Altitude (m)** as a positive number

The UI converts altitude to NED Down internally.

## Do I enter a start point?

Not for each flight.

The per-flight start is owned by the system. The first session has an **Initial UAV Position** used to spawn/setup the simulator. After a successful run, the next run automatically uses the previous measured final position as its requested start. This matters because an actual final position can differ slightly from the requested target.

Example:

```text
Requested target: N 10.00 / E 5.00 / Alt 5.00
Measured final:   N  9.84 / E 5.09 / Alt 4.98

Next flight starts from the measured final, not the ideal target.
```

## Basic workflow

1. Open the console.
2. Choose **Start / Restart Simulation**.
3. Wait until the session shows READY.
4. Enter a target or click the map.
5. Press **Bay tới điểm đích**.
6. Watch the actual trajectory and live status.
7. Review target, actual position, final error, duration and verifier result.
8. Enter another target and fly again, or press **Land**.

## Reset semantics

- Editing the target does not change vehicle state.
- `Start / Restart Simulation` destroys the current simulator session and creates a new one.
- `Land` lands the current simulated UAV without deleting historical evidence.
- The current build intentionally does not expose a “set current point to coordinate zero” action in Basic mode because rebasing coordinates can make evidence interpretation ambiguous.

## PASS / FAIL

The UI does not decide the verdict. It displays the result generated by the independent NAV-001 verifier from frozen input and frozen execution telemetry.

## Simulation only

Do not use this build to command real UAV hardware. The console and lifecycle controls are designed and tested for PX4 SITL/Gazebo simulation scope.

## 2D and 3D views

The console provides two complementary views:

- **2D Map** — best for selecting North/East targets, seeing Home/Start/UAV/Target, the planned straight-line reference and actual trajectory.
- **3D Trajectory** — an isometric view reconstructed from measured telemetry, including altitude.

The 3D trajectory view is not a replacement for Gazebo physics; it visualizes the telemetry produced by the PX4/Gazebo simulation in a browser-friendly way.
